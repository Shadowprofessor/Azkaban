# Azkaban v1 — status and run book

Branch: `v1`. Merged from `Chromium-extension` (extension), `Sachit` (ML + agent),
`yash` (RAG), `nirmit` (dashboard).

Everything below runs on **live traffic from the machine you run it on**. There is no mock
server and no sample data in any UI: with nothing running, each surface shows its waiting
state. The demo `.azk` replay still exists, but only as a test fixture.

---

## 1. Install (once)

```bash
python -m pip install -e "azkaban-agent[dev]"     # agent + mitmproxy + onnxruntime
cd azkaban-extension && npm install && cd ..      # extension (WXT, onnxruntime-web)
cd dashboard         && npm install && cd ..      # dashboard (React + Vite)
```

Or: `make install`. Python 3.11+ is what `pyproject.toml` asks for.

Copy `.env.example` to `.env` and put your key in it:

```
AZK_NIM_ENABLED=1
AZK_NIM_MODEL=nvidia/nemotron-3-ultra-550b-a55b
NVIDIA_API_KEY=nvapi-...
```

`.env` is gitignored. Verify the key actually works before relying on it:

```bash
python -m azkaban_agent nim-check
```

That prints the endpoint, the model, whether the key was accepted, and the model's reply.

## 2. Run it (four terminals, in this order)

### Terminal 1 — the agent (live capture)

```bash
python -m azkaban_agent capture --i-own-this-device
```

Binds the capture proxy on `127.0.0.1:8080` and the WebSocket on `127.0.0.1:8787`. The
`--i-own-this-device` flag is mandatory; the agent refuses to start without it.

Behind a corporate or system proxy, chain to it or every captured request fails:

```bash
AZK_UPSTREAM_PROXY=http://user:pass@proxy.corp:3128 python -m azkaban_agent capture --i-own-this-device
```

### Terminal 2 — point your traffic at the proxy

This is the step that produces real data. Nothing appears until it is done.

1. Set the system or browser proxy to `127.0.0.1:8080`.
   - Windows: Settings → Network & Internet → Proxy → Manual → `127.0.0.1:8080`
   - Or launch a dedicated browser: `chrome.exe --proxy-server="127.0.0.1:8080"`
2. Install the mitmproxy CA so HTTPS can be decrypted. With the proxy active, open
   <http://mitm.it> and follow the instructions for your OS, or import
   `~/.mitmproxy/mitmproxy-ca-cert.pem` into the trusted-root store.

Without the CA, HTTPS flows arrive with `decrypted: false` and no payload findings — hosts
and sizes only.

### Terminal 3 — the dashboard

```bash
cd dashboard && npm run dev        # http://127.0.0.1:5173
```

Accept the consent gate, then press **Start local audit**. Flows, the exposure score,
findings and verdicts arrive over the WebSocket.

### Terminal 4 — the extension

```bash
cd azkaban-extension && npm run build
# chrome://extensions -> Developer mode -> Load unpacked -> azkaban-extension/.output/chrome-mv3/
```

The popup should show a green dot and **Connected to agent**, plus the **Open Dashboard**
link. A yellow dot and **Standalone mode** means the agent is not running; the extension
still works, it just is not sharing.

## 4. What was built in v1

### Nemotron 3 Ultra 550B as the reasoning engine
`azkaban_agent/nim.py`. NVIDIA NIM, free prototyping endpoint, local Ollama as the offline
fallback. Turns itself on once `NVIDIA_API_KEY` exists; `AZK_NIM_ENABLED=0` forces it off.
Thinking is disabled in the chat template and `clean()` strips any trace, Markdown
emphasis, bullets, headers and fences, because verdicts render as plain text. Statute
quotes survive, since the citation validator checks them. Calls go through `net.py`, so the
egress guard still decides whether the request may leave at all, and the exact JSON payload
is printed first.

### Retrieval, merged from `yash`
`rag/`. The BM25 core and guide corpus from `ghostprint`, generalised so one engine serves
both corpora.

- `rag/query.py` implements `retrieve(facts, k)`, the interface `legal.py` already looked
  for, so `engines.rag` now reports `true` instead of running the stub. Ranking is hybrid:
  sections a fact implicates as a matter of law are always returned in a fixed order and
  `k` never drops them; the rest are BM25 over the statute body plus a tag boost. Sections
  gated behind a fact are demoted when the fact is absent.
- `rag/guides.py` answers what to change, mapping a destination to a guide platform and a
  finding to a category. A specific control wins over the mechanism: a GPS leak goes to
  location settings even when ad-ID profiling surfaced it. Unknown destinations get generic
  steps rather than another vendor's page, and the source is labelled either way.
- `rag/rerank.py` lets Nemotron order the retrieved sections but never add one.
- `azkaban_agent/remediate.py` attaches `data.remediation` to actionable insights.

### Dashboard, merged from `nirmit`
`dashboard/`. The UI was written against the frontend PRD, which wrapped messages in a
`data` envelope; the agent implements the frozen `lib/live/protocol.ts`, which names each
payload after its type. Connected directly it rejected every message and sat empty.
`src/adapter.js` converts the whole protocol in one place, including `flow.ts` epoch
milliseconds, numeric TCF purpose IDs, `rootHash`, the blocklist formats map and the
outbound `blocklist` action. `AgentFindings` renders agent insights with their retrieved
remediation steps. Last run of `verify:protocol`: 65/65 messages accepted, 0 dropped.

### Extension, phases 8-11
- **Phase 8** `lib/scoring.ts`: 0-100 score and A-F grade from trackers, model-flagged
  unknowns, third parties, cookies and fingerprinting. Capped per signal, caps summing to
  100, computed in one place so badge, popup and bridge cannot disagree. The breakdown and
  biggest factor are shown, because the weights are an editorial judgement.
- **Phase 9** `lib/alerts.ts` + `entrypoints/toast.content.ts`: toasts for findings worth
  interrupting for, one per subject per page, three per page maximum, rendered in a closed
  shadow root so page CSS cannot restyle a warning. Toggle in the popup.
- **Phase 10** `lib/agentBridge.ts` + `azkaban_agent/extbridge.py`: producer-only bridge.
  The extension sends findings and site scores and receives only a handshake ack — never
  flows, PII or scores — and an extension origin is refused on the dashboard path. That is
  what makes a permissive origin check acceptable, since a Chrome extension id changes on
  every unpacked reload. Reconnection runs on `browser.alarms`, which survive
  service-worker eviction. Browser detections are deliberately kept out of the exposure
  score: with the proxy also capturing, both sides see the same browser requests and
  counting them twice would inflate the number the whole UI is built on.
- **Phase 11** `scripts/package-extension.sh`, the connected-only dashboard link, and
  `azkaban-extension/README.md`.

## 5. Known gaps

- **The website is not merged.** Left alone as asked. When it is ready it connects the same
  way the dashboard does: `ws://127.0.0.1:8787`, and reuse `dashboard/src/adapter.js`
  rather than re-deriving the protocol.
- **The NVIDIA key was never called from this environment.** Both sandboxes block
  `integrate.api.nvidia.com`, so the Nemotron path is verified by unit tests over payload
  shape, output sanitising and response parsing, not by a live completion. `nim-check` on
  your machine is the real test.
- **Browser e2e needs a local Chromium.** `npx playwright install chromium` was blocked
  here, so `e2e/phase1..8.mjs` live-popup assertions skip rather than run. The pure-logic
  checks and the Python/Node bridge interop test do run.
- **Rotate the NVIDIA key.** It was pasted into a chat, so treat it as public.
- **Verdicts need an engine.** With no reachable NIM and no Ollama, flows, scores, findings
  and remediation all keep working; only DPDP verdicts pause, and the agent says so.
- **Live capture was proven on loopback traffic.** Real requests through the real proxy
  produced real flows and a score, but the sandbox's per-command proxy credentials stopped
  external hosts resolving. On your machine with direct internet there is nothing to work
  around.

## 6. Branch rules still in force

Extension work → `Chromium-extension`. Agent work → `Sachit`. Never `main`. `v1` is the
integration branch where they are merged together. `lib/schema.ts` and
`lib/live/protocol.ts` remain frozen: everything v1 added to the protocol is additive
(`engines.nim`, `engines.remediation`, `llmEngine`, `llmModel`, `extension`, and the
`/ws/extension` path).
